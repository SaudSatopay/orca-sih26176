Can I go to sea today?

ORCA already knew when the sea was dangerous. Now it knows when it doesn't know.

Before ORCA tells a fisher to go, a deterministic safety gate now checks that every critical reading is present and fresh. Old evidence earns a caution. Missing evidence earns no answer at all, and an official warning still wins every time.

Sheet 02 The challenge, scoped

Know when not to decide.

The mentor's brief, priority very high, about six hours, do not expand the scope. Objective: strengthen ORCA's most important property, trust.

Make ORCA aware not only that conditions may be dangerous, but also that it may not have enough reliable evidence to make a normal-confidence decision.

The challenge in one sentence · mentor brief, ORCA Mentor Challenge

Five required behaviours, five answers

ScenarioConditionExpected behaviourWhat ORCA does nowProof
Healthy All critical sources present and within their freshness limits The normal, existing verdict GO normal confidence · 9/100 See graph
Stale A critical input is older than its configured threshold Not the same confidence as a fresh decision, and it says why CAUTION degraded · "4 h 10 min old — over the 3 h limit" Try it live
Missing A required input is unavailable Fails safely; never invents a value or silently substitutes one INSUFFICIENT DATA no score, no invented wave height Try it live
Recovery The source becomes healthy again Back to the normal path, no restart, no code change GO "reconnected 1 min ago — readings are fresh again" See timeline
Floor compatibility The official-warning floor fires The gate never weakens it; it only adds safety NO-GO 92 and 70 held under every drill See graph

Minimum scope, delivered

  1. A data-health model: one record per input§5
  2. Configurable thresholds, overridable by environment§5
  3. A critical-input definition: wave, wind, warnings, position§5
  4. A deterministic gate step after the risk engine§4
  5. A compact explanation, and the result in the evidence path§6
  6. Automated tests and four deterministic fixtures§7

Acceptance, as the mentor checks it

  1. The healthy demo still works: Goa is 9/100, GO§6
  2. A critical input can be made stale or unavailable deterministically§6
  3. The problem is caught before a normal-confidence decision§4
  4. A clear degraded or insufficient outcome with a reason, in the evidence path too§6
  5. No new logic can reduce an official-warning floor§7
  6. The four scenarios pass from a clean start with one command§7

What we did not do

Scope discipline is part of the brief. The gate is a small deterministic step inside the existing pipeline.

  • No UI redesign: one compact strip on the existing verdict
  • No risk-engine rewrite: weights, curves and floors untouched
  • No LLM or AI feature for show: the gate is five lines of rules
  • No new languages: English, Hindi and Marathi, as before
  • No IMD, INCOIS or MOSDAC integration
  • No separate app: the gate runs inside ORCA; this page only shows it

Sheet 04 Where the gate sits

A plotted course, with two new buoys.

Every reading now carries its observation time. The freshness check runs on what the providers delivered; the gate runs after the risk engine and its floors, and before the explanation is written.

  1. 1
    Providers and cached dataOpen-Meteo (LIVE) · the rehearsed dataset (DEMO) · the warnings bulletin · the bundled chart layer
  2. 2
    Data health + freshness check newPer input: source · observed_at · age · limit · FRESH / STALE / MISSING / ERROR · critical
  3. 3
    Four agents, in parallelweather · ocean · cyclone · gis, each reporting the health of what it delivered
  4. 4
    Risk engine + safety floorsThe weighted score, then floors that only raise it: 92 · 70 · 85 · 60
  5. 5
    Safety gate newDeterministic. Splits into GO · CAUTION · NO-GO · INSUFFICIENT DATA
  6. 6
    Explanation agentThe answer, the evidence ledger and the spoken plan carry the gate's result

Five invariants, all tested

  1. The gate never changes the risk score, band or floors. It only chooses the state.
  2. If the existing logic says no-go, the state is NO-GO under every data condition.
  3. GO is only possible when every critical input is fresh.
  4. A missing input is never invented: in the unavailable drill the wave height is None, not a number.
  5. Bad data can only move ORCA toward caution, never toward "go".

Sheet 08 Recovery in LIVE mode

The feed comes back. So does the go.

With live data, nobody presses a drill chip. A failed Open-Meteo fetch is remembered for 60 seconds, then retried. When it answers, the next question is GO again.

  1. t = 0

    Provider down

    The fetch fails. The wave reading is MISSING; the gate says INSUFFICIENT DATA.

  2. 0 to 60 s

    Failure remembered

    For 60 s (CACHE_TTL_FAIL) ORCA does not hammer a dead feed; it fails fast and honestly.

  3. after 60 s

    Retried

    The next question tries Open-Meteo again.

  4. answer

    Fresh

    The series arrives with its own fetched_at; the wave is FRESH.

  5. GO

    next question

    GO again

    Normal confidence. No restart, no code change.
